# Skill: documentation

## Para qué sirve
Crear documentación breve que ayude a operar, integrar o mantener una entrega real.

## Cuándo conviene
Nuevo flujo, contrato público, integración, readme, guía de adopción o handoff.

## Entradas mínimas
Comportamiento implementado y destinatario de la documentación.

## Procedimiento concreto
1. Identificar qué necesita hacer quien lee: iniciar, cambiar, validar, depurar o continuar.
2. Derivar contenido de código/comandos y estado real; no describir flags ni capacidades inexistentes.
3. Escribir ejemplo mínimo ejecutable y limitaciones importantes.
4. Verificar paths relativos, comandos y referencias; evitar repetir reglas centrales en cada archivo.
5. Priorizar lectura corta y fácil actualización frente a manuales exhaustivos.

## Validación y salida
Docs y enlaces comprobados, ejemplos contrastados con archivos reales, supuestos visibles.

## Riesgos/limitaciones
No incorporar secretos, URLs internas sensibles ni capturas de información privada.
